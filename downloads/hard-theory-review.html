How to gain explanation marks

For an explain question, make a point, explain how it works, then say why it matters. For four marks, aim for four distinct points or two developed reason-and-effect pairs.

Networks

Peer-to-peer networks have no dedicated central server. Each computer has equal status and shares resources directly. They are simple and cheap for a small network, but security, permissions and backups are difficult to manage centrally.

Client-server networks use dedicated servers to respond to client requests. They allow central file storage, backup, user permissions and security. They suit larger networks, but servers cost money and can become a bottleneck or a single point of failure.

In a star topology, each device has a separate connection to a central switch. One cable failing affects only one device. A switch sends data only to the correct destination using MAC addresses, reducing unnecessary traffic. However, if the central switch fails, the network fails.

A router sends packets between different networks using IP addresses. A switch works within a local area network using MAC addresses. A hub sends received data to every connected device, creating unnecessary traffic and less privacy.

In packet switching, a message is split into packets. Packets contain the data plus control details, such as destination address and sequence number. They can take different routes, then are checked, reordered and reassembled at the destination.

CPU, memory and storage

For the fetch-execute cycle: the program counter, or PC, holds the address of the next instruction. Copy PC to MAR. Memory sends the instruction to MDR. Increment PC. Copy MDR to CIR. The control unit decodes the instruction. It sends control signals to execute it using the ALU, accumulator, registers or memory. Store the result.

RAM is volatile main memory for programs and data currently in use. ROM is non-volatile and stores permanent startup instructions. Cache is small, fast memory close to the CPU. It stores frequently used instructions and data, reducing CPU waiting time.

SRAM does not need refreshing. It is fast and expensive, so it is used for cache. DRAM needs refreshing, but is cheaper, so it is used as main memory. Virtual memory uses secondary storage as extra RAM, but is much slower.

An SSD uses flash memory. It has no moving parts, so it is fast, quiet and resistant to shocks, but usually costs more per gigabyte. A hard disk drive uses magnetic platters and moving heads. It provides large capacity cheaply, but is slower and more vulnerable to physical damage.

System software

An operating system manages resources. Its jobs include memory management, process management, file management, device management, security, input and output, error handling and providing a user interface.

A compiler translates the entire source program before it runs. The finished program usually runs quickly, but it must be recompiled after changes. An interpreter translates and executes one statement at a time. It is helpful during development because errors can be found near the relevant line, but the program is generally slower when it runs.

Security and databases

Authentication checks who a user is. Authorisation decides what that user is allowed to access. Encryption turns plaintext into ciphertext using a key, protecting confidentiality if data is intercepted. A digital signature helps prove who sent a message and whether it has changed.

Validation checks whether input data is sensible and follows rules, such as a range, type or format. Verification checks whether data was copied or transferred accurately. A checksum is calculated before and after transmission; a mismatch suggests data corruption.

A primary key uniquely identifies every record. A foreign key links one table to another table’s primary key. Normalisation reduces duplicated data and avoids update, insertion and deletion problems.

Algorithms and software development

Decomposition breaks a large problem into smaller parts. Abstraction removes unnecessary detail. Pattern recognition finds similarities between problems. An algorithm is a finite set of clear steps that solves a problem.

The waterfall model completes development stages in order. It suits stable requirements, but late changes are expensive. Iterative development creates a version, gains feedback, then improves it in cycles. It handles changing requirements better, but needs regular user involvement.

Testing and maintenance

A syntax error breaks the grammar rules of a language. A logic error allows a program to run but gives the wrong result. A run-time error happens while the program is running, such as division by zero.

White-box testing checks internal paths and program logic. Black-box testing checks inputs and outputs without needing knowledge of internal code. Integration testing checks that modules work together. Alpha testing is done in-house. Beta testing uses selected users before general release. Acceptance testing shows the customer that requirements have been met.

Normal test data is valid typical input and should be accepted. Extreme test data is valid input at the upper or lower accepted limit. Abnormal data is invalid and should be rejected. Boundary data tests values at or just either side of a limit.

Corrective maintenance fixes errors. Adaptive maintenance changes software for new requirements or environments. Perfective maintenance improves an already working system, for example by making it faster or easier to use.
